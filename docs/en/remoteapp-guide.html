kkguai/Guides/RemoteApp guide

Guide · about 10 minutes

Run Windows apps on a Mac, without a virtual machine

You don't need a second Windows installed inside your Mac. Windows ships with a capability called RemoteApp: the remote session publishes a single program window instead of a whole desktop. kkguai is the free, open-source macOS client that brings those windows over. This guide goes from zero to your first window.

What RemoteApp is, and how it differs from remote desktop

Remote Desktop (RDP) normally streams an entire Windows desktop into one window: you see the Windows Start menu, taskbar and wallpaper, packed into a single Mac window.

RemoteApp is the other half of RDP. The session hands the client one program window at a time, and the Windows desktop, taskbar and Start menu never appear. The app window lives on the Mac desktop: you drag it, resize it, minimise it, and put it next to your normal Mac apps.

  • The program still runs on Windows. Files, databases and intranet tools stay on that PC; the Mac only displays the window and sends input.
  • One window and one Dock icon per app. Spotlight, Launchpad and ⌘Tab find it like anything else.
  • No virtual machine. The Mac gives Windows no RAM or disk, and runs no second set of drivers.

Companies usually deploy RemoteApp through RDS or AVD. kkguai targets a different everyday case: you already have a Windows Pro PC nearby and just want its few programs on your Mac. The registry file in the release turns on the single-machine RemoteApp capability there; Microsoft doesn't ship a UI for that particular use.

What you need

There only has to be a network path between the two machines — no public IP required.
ItemRequirement
MacmacOS 14 or later on Apple Silicon (M-series). The current release does not support Intel Macs; you can build from source.
Windows hostWindows 10/11 Pro or Enterprise, or Windows Server. Windows Home cannot host RDP.
Powered onThe Windows PC stays on and connected. The programs run there; if it sleeps or shuts down, the windows go away.
NetworkSame LAN, or a path through a VPN, Tailscale or similar. Don't expose port 3389 to the open internet.
PermissionsAdministrator rights on Windows once: to enable Remote Desktop, import the registry files, and reboot.
AccountA Windows account with a password. RDP rejects blank passwords.

Windows Home: Microsoft restricts Windows Home so it cannot accept Remote Desktop connections — there is no switch to flip. Upgrade to Pro, or use a virtual machine instead (see the comparison).

Five steps to a first window

These steps assume the two machines can already reach each other. Expect about ten minutes, most of it spent waiting for Windows to reboot.

  1. Check the Windows edition and enable Remote Desktop

    On Windows, press Win + R, type winver, and confirm Pro or Enterprise. Then open Settings → System → Remote Desktop and turn it on.

    Or run these two lines in an administrator PowerShell — same result:

    Windows · Administrator PowerShell
    # Enable Remote Desktop and allow it through the firewall (language-neutral rule group ID)
Set-ItemProperty 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 0
Enable-NetFirewallRule -Group '@FirewallAPI.dll,-28752'
  2. Import enable-remoteapp.reg, then reboot

    Find enable-remoteapp.reg in the latest release and run it as administrator, or import it in Registry Editor. This step is required — it enables single-machine RemoteApp publishing.

    • If the release also contains single-session.reg, import it only if it fits your setup (see below).
    • Reboot Windows after importing so the new policy takes effect.

    If that Windows PC stays signed in to a desktop session, the dedicated app session may fail to start. single-session.reg is for that single-session case; leave it out at first and come back to it if you hit an "already signed in" error.

  3. Install kkguai on the Mac

    Download kkguai-0.2.9-macos-arm64.dmg, open it, and drag kkguai into Applications. The build is not notarized by Apple yet, so run this once before the first launch:

    macOS · Terminal
    # Remove the download quarantine flag (once per install)
xattr -dr com.apple.quarantine /Applications/kkguai.app
open /Applications/kkguai.app

    Skip it and macOS will say kkguai "is damaged" or "cannot be verified". The reason and the fix are in the FAQ.

  4. Enter the address and account, then connect

    Create a connection in kkguai with the Windows PC's hostname or IP (on a LAN that's usually something like 192.168.1.x), your username and password. On Tailscale, use the address or MagicDNS name it assigned.

    On the first connection Windows may ask you to trust its certificate; confirm it. The session itself is encrypted.

  5. Open an app from the Start menu

    You'll get a Windows 11-style Start menu listing the programs available on that PC. Click one and it becomes a separate Mac window with its own Dock icon.

    Open as many as you like afterwards — they don't interfere with each other, and each can go full screen or share the screen.

If it doesn't work

The usual suspects:

  • Connection refused or timing out: make sure Windows is the Pro edition, Remote Desktop is switched on, and the firewall allows 3389 — then ping the PC from another device.
  • No apps in the Start menu: usually enable-remoteapp.reg was never imported, or Windows wasn't rebooted afterwards.
  • "Desktop session already signed in": the same account has a desktop login on that Windows PC. Sign that session out, or use single-session.reg.
  • macOS says the app is damaged: that's the download quarantine flag, not real damage. Run the xattr command above.

A longer list lives in the troubleshooting guide; the FAQ covers the rest.
